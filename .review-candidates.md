# Raw Review Candidates (Pre-Dedup)

## Correctness Findings

### lib/utils/static.js:32-35
**readFileDirect error suppression** — Multiple angles flag the same issue:
- Angle A (34): "readFileDirect suppresses every filesystem error"
- Angle C (32): "readFileDirect's catch swallows ALL fs errors (EACCES, EISDIR, EMFILE, ENOTDIR, EBUSY, EIO…)"
- Angle E (32): "readFileDirect's empty catch swallows every fs.readFileSync error (ENOENT, EACCES, EISDIR, EMFILE, ELOOP)"

**Most concrete (Angle E:32):**
```
Failure scenario: An operator accidentally points serveStatic at a directory path 
(e.g., '/dashboard/assets' resolved to the directory itself) → fs throws EISDIR → 
readFileDirect returns null → 404 'Not found' instead of a 403/500; same with an 
unreadable file (EACCES) silently masking a misconfigured volume mount in production.
```

### lib/openrouter.js:269
**Fuzzy fallback narrowed from substring to exact equality** — Multiple angles:
- Angle A (269): "Exact normalized equality removes legitimate fuzzy matching for model keys"
- Angle C (269): "Fuzzy fallback loop now requires exact normalizedAlias === normalizedTarget equality"
- Angle E (269): "When two records share a normalized alias, cache.index ends up with LAST-written"

**Most concrete (Angle E:269):**
```
Failure scenario: Snapshot [{id:'foo', input:1}, {id:'bar', name:'Foo', input:10}] → 
cache.index.set('foo', recordB) overwrites; getOpenRouterPricingRecord('Foo') candidate 
loop hits index key 'foo' and returns recordB (input=10). If the candidate loop ever misses 
the alias (e.g., via the normalizeAlias gap on line 263), the fuzzy loop instead returns 
recordA (input=1) because A is iterated first.
```

### lib/openrouter.js:263
**normalizeAlias vs normalizeKey mismatch** (Angle E):
```
Failure scenario: Catalog entry {id: 'openai_gpt-4', name: null} → index gets key 
'openai_gpt-4' (underscore preserved); caller passes 'openai-gpt-4' → candidates = 
['openai-gpt-4', ...], none in the index, candidate loop returns null; fuzzy loop 
iterates the same record's aliases, normalizeAlias('openai_gpt-4')='openai-gpt-4' 
equals target, returns the record. Empirically reproduced at HEAD.
```

### lib/utils/static.js:53
**Dev mode fallback serves stale bytes** (Angle E):
```
Summary: In dev mode, any static path whose extension is not .js/.css/.html silently 
falls through to readFileCached, so editing a .json/.svg/.ico/.map file on disk serves 
stale bytes until restart.

Failure scenario: process.env.NODE_ENV !== 'production', filePath = '/dashboard/data.json' 
or '/styles/icons.svg' (isJS=isCSS=isHTML=false) → expression is false → readFileCached; 
developer edits the file, refreshes the page, client sees the pre-edit bytes.
```

## Efficiency/Performance

### lib/openrouter.js:264-265
**buildModelAliases rebuilt on every fuzzy fallback call** (Efficiency):
```
Summary: buildModelAliases(record) is rebuilt and a new Set allocated for every record 
on every fuzzy fallback call
Failure scenario: On each cache.index miss, getOpenRouterPricingRecord walks all 
cache.models and recomputes the alias Set the index already enumerated at buildPricingIndex 
time. Cheaper alternative: precompute normalized-alias → record once.
```

### lib/utils/static.js:53
**Every .html request triggers uncached blocking fs.readFileSync** (Efficiency):
```
Summary: Every .html request triggers an uncached blocking fs.readFileSync 
(pre-existing; the diff only lifted the call into readFileDirect, behavior unchanged).
Failure scenario: staticCache is built and never used for HTML; the highest-traffic 
entry-point (index.html) does a blocking disk read on every fetch.
```
